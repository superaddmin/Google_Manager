# 集中管理邮箱与防盗安全架构指南 (Centralized Mailbox Security Guide)

> **修订日期**：2026-09-16  
> **适用版本**：GoogleManager v2.0+ (含 Gmail API 托管、Googlemail 自动化与集中安全中控)  
> **保密级别**：内部运维与安全技术规范

---

## 1. 背景与核心挑战

在批量管理谷歌账号（成品号、业务号、开发者账号、出海资产）的场景中，邮箱不仅是账号资产的核心，更是接收资金账户、社交平台、业务系统敏感验证码的关键枢纽。

在传统分散管理模式下，操作员使用多个浏览器甚至不同网络频繁登录账号，极易导致以下安全事故：
1. **账号被盗（Account Hijacking）**：黑客获取临时访问权限后，在后台悄悄配置自动转发（Auto-Forwarding）将所有验证码转发至黑客邮箱，并删除官方告警，账号被洗空而管理员浑然不觉。
2. **环境风控与关联封号（Device Risk & Fingerprint Linking）**：操作员直接在本地浏览器登录账号获取验证码，极易触发 Google 的“可疑活动”风控锁定或手机号短信验证死循环。
3. **安全告警无法感知（Delayed Incident Awareness）**：上百个账号分散分布，当收到 Google 官方发送的“新设备登录”、“重置密码尝试”、“安全代码”等高危邮件时，管理员无法第一时间集中获知并处置。
4. **单点故障与连锁沦陷（Recovery Email Cascade Breach）**：多个账号共用弱密码恢复邮箱，一旦恢复邮箱被黑客劫持，关联的所有 Google 账号均可通过密码重置被批量盗走。

## 2. 防盗威胁模型分析 (Threat Modeling)

| 威胁类型 | 攻击手法与特征 | 传统管理痛点 | 本系统防盗对策 |
| --- | --- | --- | --- |
| **隐蔽外部转发** | 黑客在 Gmail 设置中添加 `Auto-Forwarding` 外部邮箱，截获后续所有验证码 | 管理员不进网页设置页面根本看不到 | **API 深度扫描**：定期自动调用 Gmail API 扫描全部账号的转发白名单与自动转发状态，发现外部地址秒级拉响红牌告警 |
| **恶意过滤与销毁规则** | 黑客创建 Filter，匹配 `code`、`verify`、`security` 等关键字，自动转发并移入垃圾箱（`TRASH`）或跳过收件箱 | 用户以为没收到邮件，实际上已被黑客拦截并销毁痕迹 | **规则排查引擎**：自动检测所有包含静默销毁、绕过收件箱或隐藏敏感标签的黑客规则 |
| **分散登录被木马窃密** | 员工电脑感染窃密木马（Infostealer），从浏览器提取 SQLite Cookies 和登录凭证 | 凭证落盘在多台不可控办公电脑 | **集中验证码汇聚 (OTP Hub)**：通过服务器端官方 API 读取邮件并用正则提取 OTP 验证码，操作员直接在系统面板复制验证码，全程无需登网页 |
| **弱凭证与 2FA 缺失** | 账号使用简易密码，未开启 TOTP 2FA，或 2FA 密钥泄露未轮换 | 纯密码防护在撞库攻击下极易破防 | **健康度雷达 + 自动轮换**：全库体检标注未配 2FA 账号；一键联动 Googlemail Playwright 模块自动化登录并轮换新 TOTP 密钥 |
| **应急处置不及时** | 发现某个账号异样时，找不到快捷途径阻断扩散 | 手工登录改密往往耗时太久 | **一键应急锁号**：锁定账号状态，阻断对外明文导出，写入防盗历史审计日志 |

## 3. 系统核心防盗体系设计

### 3.1 凭证隔离与 OAuth 2.0 托管
- **OAuth 2.0 令牌加密**：接入 Gmail API 时，refresh token 采用 Fernet 高强度对称密钥（`GMAIL_TOKEN_ENCRYPTION_KEY`）加密落盘，不与明文密码混用。
- **免登网页读信**：系统仅在服务器后台使用官方 API 获取必要邮件摘要，杜绝操作员在本地浏览器直接保存 Google Cookie 的风险。

### 3.2 跨邮箱验证码与安全邮件聚合流 (Central OTP & Security Feed)
- 系统提供集中验证码拉取服务（`SecurityService.get_central_otps_and_alerts`）：
  - 自动识别 Google 官方 `G-XXXXXX` 格式验证码。
  - 自动识别 Telegram, Twitter/X, OpenAI, Discord, GitHub, Binance, Microsoft 等平台的 6 位数字 OTP。
  - 自动识别“新设备登录”、“密码已被更改”、“二次验证变更”等官方安全告警邮件，并在中控台高亮置顶展示。
  - 操作员只需在“安全防盗”面板点击复制即可完成业务验证，大幅降低账号被风控或被钓鱼盗号的概率。

### 3.3 隐蔽转发与恶意黑客规则排查 (Anti-Theft Hijack Scanner)
系统周期性或由管理员一键触发全库 Gmail 扫描：
- 检索 `users().settings().getAutoForwarding(userId='me')`：排查是否有将收件自动外发到未经授权邮箱的行为。
- 检索 `users().settings().forwardingAddresses().list(userId='me')`：排查是否有已绑定的外部可疑转发白名单。
- 检索 `users().settings().filters().list(userId='me')`：排查是否存在任何匹配验证码关键词且带有删除、隐藏或转发动作的恶意规则。

### 3.4 全库安全健康度雷达与防盗评级 (Health Radar & Scoring)
针对全库账号多维度打分：
- **安全安全 (Safe, 0-29分)**：配置完整 TOTP 2FA、配置合规恢复邮箱、密码具备足够长度与复杂度。
- **中度风险 (Warning, 30-59分)**：缺失恢复邮箱或密码复杂度不足。
- **高危被盗风险 (Critical, 60-100分)**：未配置 2FA 或无恢复邮箱，处于易被撞库脱机状态。
- **已应急锁定 (Locked)**：处于被动隔离防御中，禁止数据对外导出。

### 3.5 一键防盗锁号与应急 SOP (Emergency Response)
当发现账号存在被盗嫌疑或收到异地登录告警时，执行以下应急标准流程：
1. **一键应急锁定**：在“安全防盗”面板点击“应急锁定”，系统立即将该账号标记为 `locked`，阻止前端明文复制与全库批量导出。
2. **审计记录存证**：系统自动在 `account_history` 表记录锁定时间与锁定原因。
3. **启动自动 2FA 轮换**：直接通过系统调用 `Googlemail` 自动化任务，无头浏览器登录 Google 账号并自动生成新的 20 字节 TOTP 密钥，使黑客已掌握的旧密钥彻底失效。
4. **更换恢复邮箱**：通过恢复邮箱池自动注入全新干净的恢复邮箱，斩断黑客找回路径。
5. **解除锁定并验证**：确认安全后由管理员点击“解除锁定”恢复正常流转。

## 4. 推荐生产安全运维规范

1. **强加密密钥配置**：
   - 生产环境必须配置随机生成的 `GMAIL_TOKEN_ENCRYPTION_KEY`（由 `cryptography.fernet.Fernet.generate_key()` 生成），丢失该密钥会导致已授权 Gmail 需重新授权。
2. **IP 封禁与反向代理**：
   - 系统内置 3 次密码错误封禁 24 小时机制。反向代理（Nginx/Caddy）时应正确配置 `ProxyFix`，确保真实 IP 被准确识别。
3. **最小权限原则**：
   - 定期使用“批量设置出售状态”将已交付账号标记为 `sold`，与库存成品号严格隔离。
4. **定期体检**：
   - 建议每日进入“安全防盗”中控台点击“重新体检”，检查是否有新增的高危账号或可疑转发记录。
